# One pocket per file: names from the data

A pocket's name has to be unique across its whole task group, not
just its own file — that's what lets crank find a pocket's content
even after it moves to a different file. So when a group writes one
file per item, a template's pocket needs a different name in each,
and the simplest way is to build it from the item's data, like
`// queries-{{ name }} [`.

Here `users.js` was generated earlier and given a hand-written query
inside `queries-users`; `orders.js` is new, so it gets the pocket's
default TODO. `users.js` already holds exactly what crank generates for
it, so crank leaves it alone and lists it as `(unchanged)`. Try
renaming the pocket in `model.js.tera` to just
`queries`: both files would then have a pocket called `queries`, and
crank reports the clash rather than guessing which content goes where.

## `.crank`

```yaml
taskGroups:
  - name: models
    array: models.yaml
    tasks:
      - template: model.js.tera
        output: models/{{ name }}.js
```

## `models.yaml`

```yaml
- name: users
  table: app_users
- name: orders
  table: app_orders
```

## `model.js.tera`

```text
// Generated by crank from models.yaml.
import { db } from "../db.js";

export const {{ name }} = {
  all: () => db.query("select * from {{ table }}"),
  byId: (id) => db.query("select * from {{ table }} where id = $1", [id]),
  // queries-{{ name }} [
  // TODO: add {{ name }} queries of your own here.
  // ]
};
```

## `models/users.js`

```text
// Generated by crank from models.yaml.
import { db } from "../db.js";

export const users = {
  all: () => db.query("select * from app_users"),
  byId: (id) => db.query("select * from app_users where id = $1", [id]),
  // queries-users [
  byEmail: (email) => db.query("select * from app_users where email = $1", [email]),
  // ]
};
```

## `.crank.manifest`

```yaml
version: 1
taskGroups:
  models:
  - models/users.js
```

## Output
